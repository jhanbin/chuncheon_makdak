# 춘천을 노래하다 — 관광·미식 음악 체험

다녀온 **장소**, 맛본 **음식**, 그 **순간**을 고르면 수노(Suno) AI가 나만의 노래를 만들어 주는 체험 프로그램입니다.
만든 노래는 CD 키링의 QR로 언제든 다시 들을 수 있습니다.

## 체험 흐름 (방문객 휴대폰 참여)

1. 행사장 포스터의 **입장 QR**을 휴대폰으로 스캔합니다.
2. 장소·미식·순간을 고르면 **키링 교환 번호**(No. 12 등)가 바로 나옵니다.
3. 부스에서 번호를 말하면 스태프가 `/booth`에서 찾아 CD 키링을 인쇄해 줍니다. 노래가 완성되기 전이어도 됩니다.
4. 노래가 완성되면 휴대폰에서 바로 듣습니다. 새로고침하거나 창을 닫았다 열어도 내 노래로 돌아오고, **내 앨범**에 이 휴대폰에서 만든 노래가 모입니다.

### 기본 흐름 (키오스크에서도 동일)

1. 닉네임과 연락처 뒤 4자리(선택)를 입력합니다.
2. 3단계 × 9가지 중에서 고릅니다. 조합은 모두 729가지입니다.
   - ① 장소: 가사 1절과 앨범 커버
   - ② 미식: 장르와 사운드
   - ③ 순간: 분위기와 후렴, 곡 제목
3. **노래 ID가 바로 발급**되고, 생성은 서버가 백그라운드에서 진행합니다.
4. 기다리는 동안 **CD 키링(49×37mm)을 먼저 인쇄**합니다. QR은 곡이 완성되면 자동으로 연결됩니다.
5. 곡이 완성되면 두 버전(A/B)을 들어보고 대표곡을 고릅니다. QR로 들어오면 대표곡이 먼저 재생됩니다.

## 주소

| 주소 | 용도 |
|---|---|
| `/` | 체험 화면 |
| `/?kiosk=1` | 부스 키오스크용. 3분간 조작이 없으면 처음 화면으로 돌아가고 입력값을 지웁니다 |
| `/s/{노래ID}` | QR·공유용 짧은 주소 |
| `/?code=참여코드` | **입장 QR 주소**. 방문객이 포스터 QR을 스캔하면 이 주소로 들어와 휴대폰에서 바로 참여합니다 |
| `/booth` | **부스 스태프 화면**: 교환 번호로 찾아 CD 키링 인쇄, 인쇄 여부 표시, 입장 QR 포스터(A4) 인쇄 |
| `/admin` | 운영자 대시보드: 참여 통계, 인기 조합, 실패 곡 확인, CSV 내려받기 |

## 실행

```bash
npm install
cp .env.example .env   # 값 채우기
npm start
```

API 키 없이 화면만 시연하려면 `DEMO_MODE=1`로 켭니다. 짧은 신호음이 "데모 음원" 표시와 함께 재생됩니다.

## 환경 변수 (.env)

| 변수 | 설명 |
|---|---|
| `SUNO_API_KEY` | apiframe API 키 |
| `EVENT_CODE` | 입장 코드. 설정하면 입장 QR(`/?code=…`)로 들어오거나 코드를 입력한 사람만 노래를 만들 수 있습니다. 공개 주소가 퍼져도 크레딧이 새지 않게 합니다. 비우면 누구나 참여 |
| `LIMIT_PER_DEVICE` | 휴대폰 1대당 하루 생성 수 (기본 3). 키오스크는 제외 |
| `LIMIT_PER_IP_HOUR` | 같은 인터넷 주소에서 시간당 생성 수 (기본 30). 행사장 와이파이는 여러 명이 같은 주소를 쓰므로 넉넉하게 둡니다 |
| `DAILY_LIMIT` | 하루 전체 생성 수 (기본 500). 크레딧 소진 방지 |
| `PUBLIC_BASE_URL` | Render에서는 자동으로 설정되므로 비워 두면 됩니다. QR에 들어갈 공개 주소 (예: `https://chuncheon-popup-3.onrender.com`). **키오스크를 로컬에서 돌릴 때 반드시 설정하세요.** 설정하지 않으면 QR이 localhost를 가리킵니다 |
| `DATA_DIR` | 곡 정보(songs.json)와 음원 파일을 저장할 폴더. **Render에서는 영구 디스크 경로(예: `/var/data`)를 지정해야 재배포 후에도 곡이 남습니다** |
| `ADMIN_TOKEN` | 운영자 대시보드 비밀번호 |
| `PIN_SALT` | 4자리 번호 암호화에 쓰는 임의 문자열. 운영 중에 바꾸면 기존 내 앨범 조회가 안 됩니다 |
| `SUNO_MODEL_VERSION` | 기본값 `V5`. 선택지: V4_5PLUS, V5, V5_5 등 |
| `MAX_CONCURRENT` | 동시에 생성할 곡 수 (기본 3). 초과분은 대기열에서 순서대로 처리합니다 |
| `DEMO_MODE` | `1`이면 실제 API 없이 시연 |

## Render 배포 (온라인 공개)

저장소에 있는 `render.yaml`(Blueprint)로 한 번에 만들 수 있습니다.

1. Render 대시보드에서 **New → Blueprint**를 누르고 이 저장소를 고릅니다.
2. 입력 칸이 나오면 `SUNO_API_KEY`와 `EVENT_CODE`를 채웁니다. `ADMIN_TOKEN`은 자동으로 만들어지며 서비스의 **Environment** 탭에서 확인합니다.
3. 배포가 끝나면 `https://(서비스주소)/booth`에 접속해 `ADMIN_TOKEN`을 입력하고 **입장 QR 포스터**를 인쇄합니다.

- Starter 유료 인스턴스와 1GB 디스크가 함께 만들어집니다. **무료 인스턴스는 재시작·재배포 때마다 곡 기록과 음원이 모두 사라지므로** 행사용으로 쓰면 안 됩니다.
- 디스크를 붙이면 배포할 때 몇십 초 멈춥니다. **행사 중에는 배포하지 마세요.**
- 디스크 용량은 늘릴 수만 있고 줄일 수 없습니다. 곡 1개에 약 5~8MB이므로 참여 인원에 맞게 정합니다.

## 선택지 수정

선택지 문구, 가사 줄, 수노 스타일 태그는 모두 `public/options.js` 한 파일에 있습니다.
장소 사진은 `public/assets/`에 있습니다.

## 이전 버전에서 달라진 점

- **가사를 그대로 사용**: apiframe의 `custom_mode`로 선택한 가사를 직접 넣습니다. 이전에는 설명문으로만 보냈습니다.
- **요청하자마자 ID 발급, 생성은 백그라운드**: 대기 중에 키링을 인쇄할 수 있습니다. 서버가 재시작되어도 만들던 곡을 이어서 처리합니다.
- **음원을 서버에 보관**: CDN 주소가 만료되어도 QR이 계속 작동합니다.
- **가짜 음원 대체 제거**: 이전에는 생성에 실패하면 샘플 음원(pixabay)이 그 사람의 노래로 저장되었습니다. 이제는 "실패"로 표시하고, 같은 ID로 다시 시도합니다. 이미 인쇄한 QR도 그대로 쓸 수 있습니다.
- **보안**: `songs.json`과 서버 코드가 웹으로 노출되던 문제를 막았습니다(화면 파일을 `public/`으로 분리). 닉네임에 HTML을 넣어 화면을 깨뜨리는 문제도 막았습니다.
- **키링 QR 선명도**: QR을 크게 그린 뒤 줄여서 인쇄하고, 12mm에서 14mm로 키웠으며, 주소를 짧게 줄였습니다.
- **오프라인 대비**: QR 라이브러리와 아이콘을 앱 안에 포함해, 행사장 네트워크가 불안해도 QR이 만들어집니다.
- 기존 `songs.json`의 곡은 자동으로 옮겨져 보관함에 그대로 나옵니다.
